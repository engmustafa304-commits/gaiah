# جيّة (Gaiah) — منصة حجز قاعات الزفاف وخدمات المناسبات

موقع عام (عربي/إنجليزي) + لوحة للمزودين (أصحاب القاعات) + لوحة للإدارة، فوق خادم Node.js وقاعدة SQLite.

## التشغيل المحلي

المتطلبات: **Node.js 22.5 أو أحدث** (يوجد SQLite مدمج فيه، لا حاجة لتثبيت قاعدة بيانات).

```bash
npm install        # تثبيت المكتبات
npm run dev        # تشغيل الخادم مع إعادة تشغيل تلقائية عند تعديل الكود
```

ثم افتح **http://localhost:3000**

> في ويندوز، إذا ظهر خطأ «running scripts is disabled» من PowerShell فاستعمل `npm.cmd install` و`npm.cmd run dev`، أو افتح الطرفية من نوع Command Prompt.

### حسابات التطوير (تُنشأ تلقائيًا عند أول تشغيل في وضع التطوير فقط)

| الدور | الرابط | بيانات الدخول |
|---|---|---|
| الإدارة | `/login.html?t=admin` | `admin@gaiah.local` / `Gaiah@Admin2026` |
| مزود (مجموعة اللوتس، لديه 5 قاعات) | `/login.html?t=provider` | `0551234567` / `Gaiah@2026` |
| مزودون آخرون | نفس الرابط | `0552345678` … `0555678901` / `Gaiah@2026` |

العريس/العروس **لا يحتاجان حسابًا**: يحجزان من صفحة القاعة مباشرة.

## البنية

```
public/        الواجهة (HTML/CSS/JS) — يقدّمها الخادم كما هي
  store.js     طبقة البيانات: تقرأ وتحفظ عبر الـ API
  provider.*   لوحة المزود          admin.*   لوحة الإدارة
  i18n*.js     الترجمة العربية→الإنجليزية (قاموس + قواعد)
server/
  index.js     تطبيق Express والمسارات
  scope.js     صلاحيات البيانات والتحقق من تعديلات المزود
  auth.js      كلمات المرور (scrypt) وجلسات موقّعة وتحديد المعدل
  seed.js      البيانات التجريبية
test/          اختبارات node:test
data/          قاعدة SQLite وسر الجلسات (لا تُرفع إلى Git)
```

### مسارات الـ API

| المسار | الوصول | الوظيفة |
|---|---|---|
| `GET /api/public-db` | عام | القاعات المعتمدة فقط + التقييمات الظاهرة + التواريخ المحجوزة (بلا بيانات عملاء) |
| `POST /api/bookings` | عام (محدود المعدل) | طلب حجز من الزائر |
| `POST /api/auth/login` · `logout` · `GET /api/auth/me` | — | الدخول والخروج |
| `POST /api/auth/register-provider` | عام | طلب انضمام مزود (يبقى «قيد المراجعة» حتى توثّقه الإدارة) |
| `GET/PUT /api/provider/db` | مزود | بياناته فقط؛ الخادم يتحقق من الملكية والانتقالات المسموحة |
| `GET/PUT /api/admin/db` | إدارة | كل البيانات |
| `POST /api/admin/set-password` · `reset` | إدارة | إعادة تعيين كلمة مرور مزود / إعادة ضبط (معطّل في الإنتاج) |

### الأمان المطبَّق
- كلمات المرور مشفّرة بـ scrypt، والجلسات في كوكي `HttpOnly` + `SameSite=Lax` (و`Secure` في الإنتاج) موقّعة بـ HMAC.
- حماية CSRF بترويسة مخصّصة على كل طلب معدِّل، وتحديد معدل للدخول والحجز والتسجيل.
- المزود لا يستطيع اعتماد قاعته بنفسه، ولا تعديل قاعات غيره، ولا تجاوز انتقالات حالة الحجز.
- ترويسات Helmet. (سياسة CSP الصارمة مؤجَّلة لأن الصفحات تحوي سكربتات مضمَّنة.)

## الاستضافة (الإنتاج)

### التوصية
1. **للانطلاق السريع والرخيص:** خادم افتراضي صغير (VPS) في أقرب منطقة للسعودية (البحرين/الإمارات على AWS أو Google Cloud، أو أي مزود يوفّر خوادم في المنطقة)، مع **Docker + Caddy** (شهادة HTTPS تلقائية) وقرص دائم للبيانات. هذا يناسب SQLite ويبقى التحكم كاملاً.
2. **بديل أسهل (PaaS):** Railway أو Render أو Fly.io — شرط وجود **قرص دائم (Volume)** لمجلد `/data` لأن SQLite ملف. بدونه تضيع البيانات عند كل نشر.
3. **عند النمو** (مزودون كثر، عدة خوادم): الانتقال إلى PostgreSQL مُدار وتخزين الصور في S3 (راجع «الخطوات التالية»).

> إن كان لديك التزام بإقامة البيانات داخل المملكة (نظام حماية البيانات الشخصية PDPL)، اختر مزودًا بمنطقة سعودية.

### النشر بـ Docker على VPS
الخطوات الكاملة (DNS، GitHub، `.env`، التشغيل، النسخ الاحتياطي، التحديث) في **[DEPLOY.md](DEPLOY.md)**. باختصار: `docker compose up -d --build` يشغّل التطبيق + Caddy (HTTPS تلقائي) بعد ضبط `.env`.

في الإنتاج تبدأ القاعدة **فارغة** (بلا بيانات تجريبية)؛ ادخل بحساب الإدارة وأنشئ/وثّق المزودين.

### النسخ الاحتياطي
`scripts/backup.sh` ينسخ القاعدة بأمان (`VACUUM INTO`) ويحذف النسخ الأقدم من 14 يومًا؛ جدولته في DEPLOY.md.

## قائمة قبل الإطلاق الحقيقي
- [ ] دومين + HTTPS، وتعيين `SESSION_SECRET` و`ADMIN_PASSWORD` قويين.
- [ ] جدولة نسخ احتياطي واختبار الاستعادة.
- [ ] **الصور:** تُخزَّن حاليًا داخل قاعدة البيانات (Base64). انقلها إلى ملفات/S3 عند زيادة الحجم.
- [ ] **التحقق بالرسائل (OTP)** وتسجيل العرسان إن رغبت (يلزم مزود SMS).
- [ ] **الدفع الإلكتروني** (العربون والتقسيط) عبر بوابة معتمدة، والعقود الإلكترونية.
- [ ] سياسة CSP صارمة بعد نقل السكربتات المضمّنة إلى ملفات.
- [ ] الخطوط: استضافتها محليًا بدل Google Fonts (الخصوصية والسرعة).
- [ ] صفحات الشروط والخصوصية الفعلية، ومراجعة قانونية.
- [ ] مراقبة الأخطاء (Sentry أو مشابه) وسجلات.
